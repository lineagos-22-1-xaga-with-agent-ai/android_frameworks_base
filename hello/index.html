AMS / ATMS Home 启动链路（补到客户端）

从 SystemServer 一直跟到 ActivityThread.performLaunchActivity / onCreate

完整 Markdown 版：home-start-flow.md

核心结论

  • `startHomeOnTaskDisplayArea(...)` 出现两次，通常不是死循环，而是两个入口复用。
  • 入口 A：`systemReady` 主动拉起 Home。
  • 入口 B：`resume` 阶段兜底（`no-focusable-task` / `noMoreActivities`）。
  • “到底”的后半段是 `startSpecificActivity -> realStartActivityLocked -> ClientTransaction -> ActivityThread`。

完整压缩链路

SystemServer.startOtherServices -> AMS.systemReady -> mAtmInternal.startHomeOnAllDisplays("systemReady") -> RootWindowContainer.startHomeOnTaskDisplayArea -> ActivityStartController.startHomeActivity -> ActivityStarter.execute -> executeRequest -> startActivityUnchecked -> startActivityInner -> resumeFocusedTasksTopActivities -> Task/TaskFragment.resumeTopActivity -> startSpecificActivity (if process not attached) -> realStartActivityLocked (LaunchActivityItem + ResumeActivityItem) -> ClientLifecycleManager.scheduleTransaction -> IApplicationThread.scheduleTransaction -> ActivityThread.H.EXECUTE_TRANSACTION -> LaunchActivityItem.execute -> ActivityThread.handleLaunchActivity -> performLaunchActivity -> Instrumentation.callActivityOnCreate

调试建议（最实用）

  • 第一优先打印 `EXTRA_START_REASON` / `myReason`，先分清 `systemReady` 还是兜底路径。
  • 第二优先看 `TaskFragment.resumeTopActivity` 是走 `attachedToProcess` 还是 `startSpecificActivity`。
  • 第三优先看 `realStartActivityLocked` 是否成功 `scheduleTransactionAndLifecycleItems(...)`。
  • 客户端侧看 `EXECUTE_TRANSACTION -> handleLaunchActivity -> performLaunchActivity` 是否连续出现。
